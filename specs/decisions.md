# Decisions

| ID | Date | Decision | Reason | Alternatives considered |
|---|---|---|---|---|
| D-001 | 2026-10-18 | The **API**, defined by an OpenAPI contract, is the canonical implementation. CLI, HTTP and other interfaces are thin adapters with no business logic. | One implementation to build and test. Every interface behaves the same. | CLI generated from OpenAPI; CLI calling a local HTTP service |
| D-002 | 2026-10-18 | Capture **all** completion metrics: outcome (success / failure / abandonment), time on task, attempts, error and recovery points. | All are needed to judge how well a task works. | A subset |
| D-003 | 2026-10-18 | Frequency and difficulty are held as **both** scale value and free text. **Scale is preferred** when both exist. | Interviewees speak freely; some questions request a scale. | Free text only; scale only |
| D-004 | 2026-10-18 | With several participants: use the **consensus** flow; where they differ, follow the **main speaker** and add an **annotation with timestamp** for the alternative. | Keeps one readable flow without losing dissent. | Parallel branches per participant; one diagram per participant |
| D-005 | 2026-10-18 | **Interviewer questions are excluded** from the diagram (used only as context). | The diagram describes the participant's task, not the interview. | Showing questions as annotations |
| D-006 | 2026-10-18 | Claude produces a **schema-validated Task Flow Model (JSON)**, compiled deterministically to a Mermaid `flowchart` for pele. Claude does not write Mermaid. | Testable, traceable, editable, and independent of the renderer. | Claude writes Mermaid directly |
| D-007 | 2026-10-18 | Use pele's **`flowchart`** type (not `journey`) for the task-flow view. | `journey` cannot express conditional branching. Tested: `flowchart` handles lanes, decisions, labelled edges, in-node properties and notes. | `journey`; `swimlane-beta` (same syntax, real lanes; looked clearer in a first test, under review in PT-01) |
| D-008 | 2026-10-18 | The **main speaker** is the participant with the most speaking time on the task, overridable with a `mainSpeaker` option. | Simple, measurable default with a manual escape hatch. | First speaker; most cues |
| D-009 | 2026-10-18 | **Interviewers** are named with an `interviewers` option, otherwise inferred from who asks the questions. | Labels are usually known; inference covers the rest. | Always inferred; always required |
| D-010 | 2026-10-18 | Scaled measures use a **5-point Likert scale** with labels suited to the question (difficulty: very easy → very hard; frequency: rarely → multiple times a day). **Time on task** comes from what participants say, not recording length. | Standard, comparable across interviews; recording length includes the interview itself. | 1–5 numeric only; 7-point scales |
| D-011 | 2026-10-18 | Validate the Task Flow Model with **Ajv** (`ajv@8.20.0` + `ajv-formats@3.0.1`, JSON Schema 2020-12), followed by our own semantic rules (DS-10 to DS-20). | De-facto standard JSON Schema validator for Node; small and mature. | Hand-written validation; Zod (would duplicate the JSON Schema the API and OpenAPI need) |
| D-012 | 2026-10-18 | Step **attributes** describe the step (e.g. tool used); **states** describe the condition of something at that step (e.g. payment declined). Both are name/value pairs. | Confirmed distinction; simple, flexible structure. | Fixed fields per attribute type |
| D-013 | 2026-10-18 | **Errors are separate error flows**, each rendered as its own diagram. The main flow links out from the trigger step; an error flow that resumes the task links back to the main-flow step it returns to. Standard visuals: **hexagon** for error link-out/entry, **double circle** for error return/re-entry, red dashed edges. Error flows don't nest (for now). | Keeps the main flow readable; makes error handling a first-class, reviewable flow. | Per-step error markers + retry loops in the main diagram (previous draft) |
| D-014 | 2026-10-18 | Measures carry an optional binary **`threshold`** (`above` / `below`) for participants' judgements against their own tolerance; **above = frustration signal**. Outcomes and error triggers carry a **frequency** measure. | Interviewees are often binary about frequency/difficulty; the side of the threshold indicates frustration. | Forcing binary statements onto the Likert scale |
| D-015 | 2026-10-18 | The document stores the **fully qualified path** to its VTT file (plus SHA-256), not cue text. The API exposes **`GET /flows/{flowId}/path`** returning that path. The main flow and its error flows' SVGs are always written to the **same directory** and linked by relative file name. | Avoids duplicating personal data; evidence can still be reviewed from the source. Same-directory output keeps cross-diagram links simple. | Storing cue text; absolute links between SVGs |
| D-016 | 2026-10-18 | **Non-linear accounts:** the flow follows task order, not telling order; later detail enriches existing steps; a participant's **corrections win** and are recorded as `correction` annotations (unresolved self-contradictions: the later statement wins, flagged the same way). Extraction sends the **whole transcript in one request**, never sequential chunks. | Real interviews jump back and forth, add detail late and include corrections; a cue's meaning can depend on anything said earlier or later. | Telling order; first statement wins; chunked extraction |
| D-017 | 2026-10-18 | **All diagram styling is CSS.** The compiler emits semantic class names only (no `classDef`/`style`/`linkStyle`). A default theme (`styles/journey.css`, zero-specificity `:where()` selectors) is embedded by default; corporate stylesheets can be **embedded** or **linked** (`<?xml-stylesheet?>`) and always override the default. | A corporate stylesheet must be able to style all output consistently; inline styles from Mermaid would block it. | Mermaid `classDef` colours; pele theme options only |
| D-018 | 2026-10-18 | The default theme is based on the **IBM Carbon Design System** (v11): Carbon token names (`--cds-*`), White theme for light and Gray 100 for dark (`prefers-color-scheme`), IBM Plex Sans, square corners. | Requested; gives a consistent, accessible, well-documented basis that Carbon-based corporate styles can plug into via the same tokens. | pele's default look; a bespoke palette |
| D-019 | 2026-10-18 | **Loops are explicit.** Each flow has `loops`: `repeat` (count as a number, or as text when it varies, e.g. "for each receipt"; no decision, no back transition) and `iterate` (decision with pass/fail branches, typical iterations, optional limit that **triggers an error flow**). Drawn as a loop marker on a dashed loop-back path (↻ × n / ↻ until …). Every cycle must be a declared iteration; loops nest cleanly. | Interviews describe both fixed repetition and repeat-until-pass; making them explicit makes them checkable and drawable to a standard, as with error flows. | Implicit cycles only; unrolling repeats; badges on every step; limit as a plain outcome |
